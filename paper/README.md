# Paper analyses and figures

Everything here imports the application code unchanged (`backend/...`) and re-runs the study's own pipeline, service-grouped split and model factory. With the real dataset in place, `reviewer_analyses.py` first reproduces the official 25-fold macro-F1 values bit for bit (LR 0.6339526050735212, XGBoost 0.5915302092371963, RF 0.5386608264991757) and the locked holdout confusion matrix, and stops if it cannot; only then does it run the additional analyses reported in the paper (label vs recorded outcomes, heuristic baselines, paired fold-level tests, holdout bootstrap, two-way rule audit, same-service Dev-label baseline, threshold analysis, ordinal metrics). `qa_compare.py` and `owner_sensitivity.py` hold the subset and the Owner_Availability sensitivity analyses. Results used in the paper are in `results/`.

```bash
pip install -r paper/requirements-pinned.txt      # the exact library versions of the study (see Appendix A of the paper)
python paper/reviewer_analyses.py
python paper/qa_compare.py
python paper/owner_sensitivity.py
python paper/r11_presubmission_analyses.py        # criteria-only baseline, High-vs-rest screening, operational value, wave-ordered transfer, calibration, 20-permutation importance (Sections 4.2-4.6)
python paper/r12_revision_analyses.py             # Table 5 Holm and Benjamini-Hochberg adjustments; Table 7 label ceiling, criteria-only row, service bootstrap, failure-trained model (Sections 4.2-4.3)
python paper/external_check/stage1_freeze_predictions.py <new_services.xlsx>   # Section 4.9: freeze predictions for unseen records (see paper/external_check/README.md)
python paper/external_check/stage2_compare.py <labels.xlsx>                     # Section 4.9: compare with the ratings requested after the freeze
python paper/figures/make_figures.py              # Figures 1-5 (needs the real workbook for Figure 1 and the class counts; every plotted value is asserted)
python paper/figures/make_fig6.py                 # Figures 6-7 (architecture; annotated screen)
```

Which file holds which number: `results/reviewer_analyses.json` is the main run (its B2 paired differences use the population SD, ddof = 0, and its subset scores use the labels present in each fold); `results/table5_sd.json` gives the Table 5 differences under both SD conventions — the paper reports every ± value with 25 in the denominator (`sd_ddof0`), and the corrected resampled t-test uses the sample variance (df = 24); `results/recheck_v4.json` gives the fixed-label subset scores quoted in Section 4.5 (Dev rows 0.624 ± 0.151) and the like-for-like threshold comparison of Section 4.3; `results/owner_sensitivity*.json` and `results/r2_fixes_numbers.json` give the Owner_Availability sensitivity figures of Section 4.6 and the Low-record counts of Section 4.5; `results/r11_presubmission_analyses.json` holds every number added in the November 2026 version (Table 4 High-vs-rest columns, Table 5 criteria-only rows, Table 7, the holdout re-summary of Table 8, Section 4.5 wave-ordered transfer, calibration and the 20-permutation importance of Figure 5), all computed in the selection pool with the holdout closed. `results/per_fold_metrics.csv` gives the 25 per-fold values of every metric for every model and baseline of Tables 4-6, the Dev/QA subset and wave-ordered analyses of Section 4.5 and the binary any-problem analysis of Section 4.3 (columns: analysis, fold, repeat, subset, model, metric, value; no record-level information), and `results/oof_confusion_matrices.json` the out-of-fold confusion matrices of the three classifiers per repeat; together they let every test, interval and fold count of the paper be recomputed without the record-level data. `results/r12_revision_analyses.json` holds the Holm and Benjamini-Hochberg adjusted p values of Table 5, the Table 7 rows added in November 2026 (label ceiling, criteria-only model, rule count >= 3), the service-level bootstrap of the LR-minus-rule-count differences and the failure-trained model (Section 4.3). `external_check/` holds the blind external check of Section 4.9: `PROTOCOL.md` (pre-specified, frozen before the ratings were requested), `freeze_manifest.json` (time and SHA-256 of the frozen predictions, committed as 14d6d1c on 6-7 November 2026 before the ratings were requested) and `external_check_table.md` (the aggregate results of Table 10); the 14 records and their predictions are withheld with the record-level data.

On the synthetic example the reproduction gate fails by design (the numbers belong to the real data); the scripts then exit with the gate assertion. The scripts are provided so that reviewers can read exactly what was computed and run it on the real data under the organization's authorization.
